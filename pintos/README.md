# 📋 팀 개발 규칙 (Development Convention)

> 본 문서는 팀의 원활한 협업과 일관된 코드 관리를 위한 개발 규칙입니다.
> 아래 규칙은 팀 검토 후 최종 확정합니다.

## 1. 작업 시작

1. 담당 Jira 이슈의 작업 범위와 완료 기준을 확인한다.
2. 최신 `main` 코드를 반영한다.
3. 작업 브랜치를 생성한다.
4. Jira 이슈 상태를 `진행 중`으로 변경한다.

## 2. 브랜치 네이밍 규칙

**형식**

```
유형/Jira이슈키-작업명
```

**예시**

```
feat/KAN-7-alarm-clock
fix/KAN-6-priority-donation
docs/KAN-5-build-guide
```

**규칙**
- Jira 이슈 키를 반드시 포함한다.
- 작업명은 짧은 영문 소문자와 하이픈(`-`)을 사용한다.
- 브랜치 이름만으로 작업 내용을 파악할 수 있도록 작성한다.

## 3. 커밋 메시지 규칙

**형식**

```
유형: 변경 내용
```

**예시**

```
feat: sleeping thread 관리 추가
fix: priority 갱신 조건 수정
docs: 빌드 명령 정리
```

**커밋 유형**

| 유형 | 설명 |
|------|------|
| `feat` | 새로운 기능 추가 |
| `fix` | 버그 및 오류 수정 |
| `refactor` | 기존 동작을 유지하면서 코드 구조 개선 |
| `docs` | 문서 작성 및 수정 |
| `test` | 테스트 코드 추가 및 수정 |

**규칙**
- 하나의 커밋에는 하나의 목적만 담는다.
- 변경 내용을 명확하고 간결하게 작성한다.

## 4. 코딩 컨벤션

- 기존 Pintos 코드의 들여쓰기와 중괄호 스타일을 따른다.
- 주변 코드와 일관된 네이밍 방식을 사용한다.
- 함수와 변수는 역할이 명확하게 드러나도록 작성한다.
- 주석에는 코드만으로 드러나지 않는 이유와 제약 사항을 작성한다.
- 공통 자료구조나 함수 인터페이스를 변경하기 전에 팀원들과 논의한다.
- 작업과 관련 없는 파일의 전체 포맷 변경은 지양한다.

## 5. Pull Request (PR) 규칙

### PR 제목

**형식**

```
[Jira 이슈 키] 변경 내용
```

**예시**

```
[KAN-5] 알람 기능 구현
```

### PR 본문

PR에는 다음 내용을 포함한다.

- **관련 이슈**: Jira 이슈 링크
- **해결하려는 문제**: 작업 배경 및 목적
- **주요 변경 사항**: 구현 내용과 해당 방식을 선택한 이유
- **테스트 결과**: 실행한 테스트, 명령어 및 결과
- **리뷰 요청 사항**: 리뷰어가 집중해서 확인할 부분

PR 작성 후 리뷰를 요청하면 Jira 이슈 상태를 `검토 중`으로 변경한다.

## 6. 코드 리뷰 및 병합 규칙

### 리뷰 규칙

- PR 작성자는 다른 팀원에게 코드 리뷰를 요청한다.
- 최소 **1명 이상의 승인(Approve)** 을 받아야 한다.
- 리뷰 과정에서 제기된 필수 수정 사항을 해결한다.
- 관련 테스트가 정상적으로 통과해야 한다.
- 기존 베이스 코드의 실패와 이번 변경으로 발생한 실패를 구분한다.

### 병합 규칙

- **`master` 브랜치에 직접 push하지 않는다.**
- 모든 변경 사항은 PR을 통해 병합한다.
- 작성자가 승인 조건과 테스트 결과를 확인한 후 병합한다.
- 병합 방식은 **Merge Commit**을 사용한다.

구현 이슈는 `master` 병합 및 완료 기준 충족 후 Jira 상태를 `완료`로 변경한다.

## 7. 일일 리뷰 및 병합

**진행 시간: 매일 21:00 ~ 23:00**

진행 내용은 다음과 같다.

1. Jira 보드를 통해 작업 진행 상황을 공유한다.
2. 개발 중 발생한 문제와 블로커를 공유한다.
3. 병합 예정인 PR을 검토한다.
4. 코드 충돌 및 작업 간 의존 관계를 확인한다.
5. PR 병합 후 팀원들은 최신 `master` 코드를 반영한다.
6. 다음 작업의 담당자와 우선순위를 확인한다.

## 8. 구현 분담 및 협업 규칙

- 구현 전에 설계 방향과 기능 간 연결 지점을 합의한다.
- 같은 파일을 동시에 수정해야 하는 경우 수정 범위를 사전에 공유한다.
- 실제 담당 작업과 일정은 Jira에서 관리한다.
- 작업 분담 변경이 필요한 경우 팀원들과 논의한 후 Jira에 반영한다.

---

> 모든 팀원은 위 규칙을 준수하며, 변경이 필요한 사항은 팀 논의를 통해 결정합니다.
